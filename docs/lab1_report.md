# Отчёт по ЛР1

## Выполненный уровень

Выполнены базовый уровень и базовый+ (С1–С10). Из базового++ выбраны:

- **П2** — покрытие не ниже 90 %: порог `--cov-fail-under=90` задан в `pyproject.toml`
  и в CI. Тесты проверяют настройки по умолчанию, чтение из окружения и `.env`,
  валидацию, маскирование токена, CLI и логирование.
- **П3** — JSON-логи: класс `JsonFormatter` выводит одну JSON-строку на запись,
  формат переключается переменной `RG_LOG_FORMAT` (`text` / `json`). Есть тест,
  который разбирает строку лога через `json.loads`.

## Затруднения

- Тесты CLI вызывают `setup_logging`, и обработчик логов оставался висеть на потоке
  `CliRunner` после завершения теста. Добавил фикстуру, которая после каждого теста
  удаляет обработчики корневого логгера.
- Разработка на Windows: git ругался на переносы строк (LF/CRLF). Для проверки
  форматирования это не критично, ruff сам приводит файлы к одному виду.

## Отличия от примера из лекции

- `log_level` и `log_format` объявлены через `Literal`, поэтому опечатка в уровне логов
  сразу даёт ошибку валидации, а не молча ломает логирование.
- Хуки ruff и mypy в pre-commit запускаются через `uv run`, чтобы использовались те же
  версии, что в `uv.lock`, и mypy видел все зависимости проекта.
- Тема проекта своя (датасет MASSIVE), поэтому пакет называется `massive_assistant`,
  но команда CLI оставлена `rg`, как в задании.
